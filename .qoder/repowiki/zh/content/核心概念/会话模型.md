## 简介
本文件系统性阐述 RDC-Tool 的会话模型，聚焦以下目标：
- Replay 会话的生命周期管理：创建、打开捕获、状态切换、销毁与资源清理。
- 上下文快照机制：保存和恢复运行时状态，支持多上下文隔离。
- Daemon context 的概念与使用方式：上下文隔离、占用限制、清理策略，以及基于 Windows 文件锁的所有权机制。
- 预览状态管理：帧缓冲预览、窗口适配、显示区域计算。
- 嵌入式回放观察机制：PNG 导出、事件选择、目标指定、最终输出判定。
- Android 辅助工具的会话生命周期：连接管理、进程所有权、资源清理。
- 提供具体代码示例与 API 调用模式，帮助开发者理解内部实现。

## 项目结构
RDC-Tool 将"会话"抽象为跨本地/远端的 RenderDoc 回放控制器实例，并通过上下文（daemon context）进行隔离。关键模块职责如下：
- rdc_tool/core/session_manager.py：会话管理器，封装本地/远端渲染后端初始化、捕获打开、无头输出创建、清理等。
- rdc_tool/server_runtime.py：运行时服务，维护上下文状态、会话映射、预览绑定、远程句柄、快照同步等。
- rdc_tool/context_snapshot.py：上下文快照持久化与归一化，支持用户字段与运行时字段分离、保留策略。
- rdc_tool/replay_observation.py：嵌入式回放观察，导出 PNG、选择事件与目标、判定最终输出、返回 revision 与错误信息。
- rdc_tool/remote_bootstrap.py：Android 辅助工具引导，设备发现、APK 安装、端口转发、进程所有权与清理。
- rdc_tool/preview_window.py：Windows 预览窗口宿主，帧缓冲几何适配、窗口尺寸调整、消息循环。
- rdc_tool/models.py：会话能力、捕获信息、事件树等数据模型。
- rdc_tool/runtime_worker.py：独立工作进程，维持一个事件循环与单线程执行器以保障原生线程亲和性。
- rdc_tool/daemon/ownership.py：进程级 daemon 所有权管理与序列化状态发布，包含 OwnerLease 类和 locked_publication 上下文管理器。
- rdc_tool/daemon/server.py：Daemon 服务器实现，使用命名管道通信，集成 OwnerLease 维持独占所有权。
- rdc_tool/daemon/client.py：客户端工具函数，包含启动锁、状态管理、所有权验证等功能。
- docs/session-model.md：官方会话模型文档，定义行为契约与约束。

- RuntimeState：运行时状态容器，维护 captures、replays、remotes、previews、shader debug、快照等。

- PreviewWindowHost：Windows 预览窗口，帧缓冲几何适配、窗口尺寸自动调整、消息循环。

#### 所有权机制重大重构

##### OwnerLease 类
`OwnerLease` 类使用 Windows 文件锁维持独占所有权直至进程退出，包括 teardown 期间。其核心特性包括：

- **文件锁机制**：使用 `msvcrt.locking()` 获取非阻塞锁，锁文件名为 `{state_path}.owner.lock`
- **进程级租约**：锁持有者即为上下文所有者，锁在进程退出前持续有效
- **防并发冲突**：若锁已被占用，抛出 `DaemonOwnerUnavailable` 异常
- **Teardown 保护**：即使监听器关闭或工作线程停止，锁仍保持直至进程完全退出

```python
class OwnerLease:
    """Keep this handle alive until the owning process exits, including teardown."""
    
    def __init__(self, path: Path, context: str) -> None:
        self.path = path.resolve()
        path.parent.mkdir(parents=True, exist_ok=True)
        self.handle = path.with_suffix(".owner.lock").open("a+b")
        try:
            acquired = try_lock(self.handle)
        except BaseException:
            self.handle.close()
            raise
        if not acquired:
            self.handle.close()
            raise DaemonOwnerUnavailable(context, path, "owner_lock_busy")
```

##### locked_publication 上下文管理器
`locked_publication` 确保有界期限内的序列化状态发布，防止并发写入损坏 daemon 状态：

- **序列化写入**：使用独立的 `.publish.lock` 文件确保同一时刻只有一个写入者
- **有界等待**：最多等待 5 秒获取发布锁，超时抛出 `DaemonOwnerUnavailable`
- **身份验证**：写入前验证当前状态的 PID、pipe_name 和 token 是否与预期所有者一致
- **原子性保证**：配合 `atomic_write_json` 确保状态文件写入的原子性

```python
@contextmanager
def locked_publication(path: Path, context: str):
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.with_suffix(".publish.lock").open("a+b") as handle:
        deadline = time.monotonic() + 5.0
        while not try_lock(handle):
            if time.monotonic() >= deadline:
                raise DaemonOwnerUnavailable(context, path, "state_publication_busy")
            time.sleep(0.01)
        try:
            yield
        finally:
            unlock(handle)
```

##### 启动锁与所有权锁的分离
系统现在采用两层锁机制：

1. **启动锁（`.start.lock`）**：
   - 用途：等待子进程 daemon 就绪，避免竞态条件
   - 范围：仅覆盖启动阶段，不影响所有权
   - 超时：30 秒，轮询间隔 50 毫秒
   - 实现：结合线程互斥锁和文件锁

2. **所有权锁（`.owner.lock`）**：
   - 用途：维持进程级独占所有权
   - 范围：整个进程生命周期，包括 teardown
   - 释放：仅在进程退出时由操作系统自动释放
   - 实现：`OwnerLease` 类管理的非阻塞文件锁

这种分离使得调用方可以等待子进程就绪而不阻塞所有权获取，提高了系统的并发性和响应性。

##### Daemon 服务器集成
`DaemonRuntime` 在 `serve_forever()` 中获取 `OwnerLease`，并将其添加到全局 `_PROCESS_OWNER_LEASES` 列表中：

- **启动时获取**：在监听器创建前获取所有权锁
- **状态持久化验证**：`_persist_state()` 检查 `_owner_lease` 是否存在
- **进程退出保护**：使用 `os._exit(0)` 确保进程快速退出，锁由 OS 释放
- **全局租约列表**：`_PROCESS_OWNER_LEASES` 防止 Python 垃圾回收提前关闭锁


## 性能考虑
- 单线程执行器：runtime_worker 使用 ThreadPoolExecutor(max_workers=1) 保持原生线程亲和，避免每请求创建事件循环导致原生上下文失效。
- 异步卸载：SessionManager._offload 将阻塞操作放入线程池，避免阻塞事件循环。
- 快照保留策略：last_artifacts 按 total_limit/per_type_limit 裁剪，减少磁盘与序列化开销。
- 预览窗口自适应：基于屏幕工作区与缩放比例计算窗口尺寸，避免过度重绘。
- 远端传输进度：CopyCaptureToRemote/ADB push 回调进度，便于 UI 反馈与超时控制。
- **所有权锁优化**：启动锁与所有权锁分离，避免长时间持有启动锁阻塞其他操作。
- **序列化发布**：locked_publication 使用短超时（5秒）和快速轮询（10毫秒），最小化等待时间。

## 故障排查指南
- 会话冲突：create_session 已存在相同 session_id 抛出 session_conflict。
- 控制器缺失：open_capture 后 controller 为空抛出 controller_missing。
- 远端复制失败：remote_capture_copy_failed，details 包含 copy_error。
- 观察路径无效：out_path 必须为绝对 PNG 路径且不存在；final_output 不能与 event_id/target 组合。
- 目标缺失：no_color_output/missing_target/export_failure 分别对应无颜色输出、目标不存在、导出失败。
- Android 辅助工具：adb_unavailable/android_apk_install_failed/android_remote_launch_failed/android_helper_ownership_changed 等错误码。
- **所有权相关错误**：
  - `daemon_owner_unavailable`：所有权锁被占用或状态文件无效，包含 recovery_hint 指导恢复
  - `owner_lock_busy`：尝试获取已被占用的所有权锁
  - `state_publication_busy`：状态发布锁超时（5秒）
  - `state_owner_changed`：检测到状态所有者身份变化（PID/pipe_name/token 不匹配）
  - `owner_lease_closed`：OwnerLease 已关闭或路径/PID 不匹配
  - `daemon_start_lock_timeout`：启动锁获取超时（30秒）

**恢复策略**：
- 对于 `daemon_owner_unavailable`：保留所有者及其状态，重试状态查询；显式清除/停止已识别的所有者并确认进程退出后再启动替代者
- 对于启动锁超时：等待并重试相同上下文；不要停止活动所有者或移除其状态/锁
- 对于状态所有者变更：验证当前活跃进程，必要时使用 `daemon stop` 清理旧状态

## 结论
RDC-Tool 的会话模型以 SessionManager 为核心，结合 server_runtime 的上下文隔离与快照机制，实现了本地/远端一致的 Replay 生命周期管理。预览与观察功能提供了灵活的可视化与取证能力，Android 辅助工具确保了移动端调试的端到端闭环。通过严格的错误分类、资源清理与保留策略，系统在稳定性与可维护性方面具备良好基础。

**新增的所有权机制**通过 OwnerLease 类和 locked_publication 上下文管理器，提供了进程级的独占所有权保证和序列化的状态发布保护。启动锁与所有权锁的分离设计提高了系统的并发性和响应性，同时保持了强一致性保证。这些改进显著增强了多上下文环境下的安全性和可靠性。
