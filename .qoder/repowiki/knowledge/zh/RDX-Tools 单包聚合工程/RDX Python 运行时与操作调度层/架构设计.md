模块以 server.py 作为统一入口，通过 `__getattr__` 延迟加载 server_runtime（本地或远程后端），并由 CoreEngine（core/engine.py）统一执行：tool_router.build_operation_registry() 从 runtime_catalog.load_tool_catalog() 读取 operation_definitions.OPERATIONS，按 rd.<domain>.<action> 三段式命名分发到 handlers/<domain>.handle(action, args, env)；每个 handler 再委派给 core/* 中的服务（session_manager、capture_queries、replay_read、pipeline_service、diff_service、render_service 等）。执行上下文由 ExecutionContext 携带 trace_id、transport、metadata，并通过 ProgressReporter 上报进度。守护进程层位于 daemon/server.py，使用 Windows 命名管道 \\.\pipe\... 暴露 RPC，维护 DaemonRuntime.state 并管理 RuntimeWorkerProcess（daemon/worker.py）；工作进程由 runtime_worker.py 启动，通过 stdin/stdout JSON 协议接收 exec/clear_context/status/shutdown 方法调用，在单线程 asyncio.Runner 中执行 server.dispatch_operation，并以独立线程监控父进程退出。状态持久化通过 context_snapshot、runtime_state、daemon/client.save_daemon_state 写入 cli_runtime_dir() 下的 JSON 文件，支持多 context（default 与带安全化后缀）。错误经 core/errors.map_exception 映射为 canonical_error，成功结果经 contracts.canonical_success 包装并自动发布 artifacts。
