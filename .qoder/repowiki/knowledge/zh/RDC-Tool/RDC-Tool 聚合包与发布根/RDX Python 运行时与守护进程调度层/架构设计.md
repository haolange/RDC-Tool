模块以 rdc_tool/server.py 作为对外入口，通过 `__getattr__` 延迟加载 server_runtime，并在首次调用时构建 CoreEngine（core/engine.py）+ ArtifactPublisher；server_runtime.py 维护全局 RuntimeState、SessionManager、RenderService、PipelineService、PerfService、EventGraphService、PatchEngine 等核心服务，并通过 contextvars 在请求级传播 _CURRENT_CONTEXT_ID 与 _CURRENT_PROGRESS_REPORTER。操作分发由 tool_router.build_operation_registry() 从 runtime_catalog.load_tool_catalog() 读取 operation_definitions.OPERATIONS，按 rd.<domain>.<action> 三段式命名映射到 handlers/<domain>.handle(action, args, env)，每个 handler 再委派给 core/* 中的具体服务。执行上下文 ExecutionContext 携带 trace_id、transport、metadata，ProgressReporter 上报进度。守护进程层 daemon/server.py 使用 Windows 命名管道 \\.\pipe\... 暴露 RPC，DaemonRuntime 维护 state 并通过 daemon/client.save_daemon_state 持久化到 cli_runtime_dir() 下的 JSON 文件；daemon/worker.py 启动 RuntimeWorkerProcess，工作进程 runtime_worker.py 通过 stdin/stdout JSON 协议接收 exec/clear_context/status/shutdown 方法调用，在单线程 asyncio.Runner + ThreadPoolExecutor(max_workers=1) 中复用渲染回放线程，避免原生句柄失效。状态持久化通过 context_snapshot、runtime_state、daemon/client.save_daemon_state 写入 cli_runtime_dir() 下的 JSON 文件，文件名按 context 安全化区分 default 与自定义 context。异常经 core/errors.map_exception 映射为 canonical_error，成功结果经 contracts.canonical_success 包装并自动发布 artifacts。
