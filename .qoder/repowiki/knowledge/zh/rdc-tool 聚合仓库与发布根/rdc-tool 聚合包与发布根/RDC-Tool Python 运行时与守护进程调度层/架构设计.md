模块以 `pyproject.toml` 暴露 `rdc-tool` CLI 入口，内部按职责划分为四层：
- CLI 与路由层：`cli.py` / `cli_batch.py` 通过 `tool_router.py` 将 `rd.<domain>.<op>` 调用（buffer/capture/core/debug/diag/event/export/macro/mesh/perf/pipeline/remote/replay/resource/session/shader/texture/util/vfs）分派到 `handlers/` 下的领域处理器；`server_runtime.py` 是核心执行引擎，封装 `CoreEngine`、上下文快照、预览窗口与工具目录注册。
- 守护进程调度层：`daemon/server.py` 基于 `multiprocessing.connection.Listener`（Windows 命名管道）监听 RPC，持有 `RuntimeWorkerProcess`（`daemon/worker.py`），通过 `client.py` 的 `DaemonStartLock` + 文件锁协调多进程并发启动，并使用 `ownership.py` 实现 owner lease 防止所有者退出后资源泄漏。
- Worker 子进程层：`runtime_worker.py` 作为独立 Python 解释器加载 `server_runtime`，通过 JSON-over-stdout 协议向父进程回传进度事件，隔离对 RenderDoc 原生 DLL 的导入。
- 运行时代发现与安装层：`runtime_bootstrap.py` / `python_runtime.py` / `runtime_paths.py` / `runtime_identity.py` / `runtime_requirements.py` 负责解析 `binaries/` 布局、注入 `sys.path`、注册 `.dll` 目录、校验 manifest 并选择可执行环境；`remote_bootstrap.py` / `android_install_state.py` / `android_apk_identity.py` 处理 Android 远端 APK 的安装与身份识别。
依赖方向单向：CLI → daemon client → server → worker → server_runtime → handlers → core/*，逆向不可达。`spec/tool_catalog.json` 由外部生成，驱动 `tool_catalog.json` 注册表，使新增工具无需修改路由逻辑。
