本仓库以 `pyproject.toml` 为单一发布描述符，通过 setuptools 将 `rdc_tool/*` 子包打包为 `rdc-tool` 可分发包，并在 `[project.scripts]` 中暴露 `rdc-tool` CLI 入口。

跨子模块的协作契约集中在以下几处：
- `spec/tool_catalog.json` + `spec/build_catalog.py` + `spec/validate_catalog.py` 定义工具能力目录，CI 在 `contract` job 中运行校验并生成 tool-reference，确保 `rdc_tool/handlers/*.py` 暴露的操作与 catalog 保持一致。
- `intermediate/native-replay/` 下的 JSON fixture 是 host/agent 交互的基线快照，被 `tests/test_native_replay_health.py` 等用例消费，形成跨 Android 原生回放、Python runtime 和 CLI 的端到端回归基线。
- `binaries/`（Windows x64 与 Android arm32/arm64）由 `scripts/package_runtime.py` / `scripts/release_runtime.py` 在构建阶段注入到运行时目录，与 `rdc_tool/runtime_*` 模块共同完成二进制发现与版本对齐。
- `.github/workflows/ci.yml` 串联三个 gate：catalog contract 检查 → 无捕获文件 doctor 冒烟 → tag 身份校验 + `scripts/package_release.py` 打包，产出 `dist/rdc-tool-*-windows-x64.zip`。

因此，子模块之间不直接互相 import，而是通过 catalog schema、JSON 回放基线和脚本/CI 这三个共享边界进行耦合。
