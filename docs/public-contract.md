# Public Contract

The public user surface is the `rdc-tool` CLI command. Release packages also include platform launcher files such as `bin/rdc-tool.cmd`, `bin/rdc-tool`, and `bundled-python cli/run_cli.py` for installation diagnostics and maintainer use.

`rdc-tool` keeps the canonical JSON envelope stable while replacing the public operation set. Use `rdc-tool version --json` to inspect the tool version, schema version, platform, entrypoints, and public contract metadata.

The current contract removes obsolete and misleading operations without aliases or forwarding handlers. The code-owned definitions, generated catalog, generated reference, registry, and CLI discovery must describe the same operation set and content fingerprint, derived from code. The migration table in [tool-interface-upgrade.md](tool-interface-upgrade.md) explains replacements; it is documentation and is never consulted at runtime.

`--daemon-context <id>` selects an isolated CLI runtime namespace. It is not an ownership claim or task handoff mechanism; callers choose and manage context ids in their own orchestration layer.

The JSON envelope remains stable across this interface break. Unknown operations and unknown parameters fail before execution; the runtime does not translate old names or ambiguous parameter aliases.

Canonical JSON never emits the non-standard bare numeric tokens `NaN`, `Infinity`, or `-Infinity`. When native shader or capture data contains a non-finite floating-point value, the corresponding value remains present as the explicit string `"NaN"`, `"Infinity"`, or `"-Infinity"`; finite numbers remain numbers. A marker describes the observed native value, not a substituted zero or a successful measurement. Consumers must treat those strings as non-finite data when interpreting numeric arrays.

Dispatched native operation results include `meta.process_identity`; `rd.session.get_context` also exposes it in `data`. CLI discovery, version and doctor do not execute a worker operation and do not establish process continuity. An actual daemon child reports both its own and its parent daemon's PID and OS process-birth `start_generation`. These values come from live OS queries, not persisted replay IDs or editable context fields. Missing parent ownership, inaccessible process birth or an unsupported platform yields `status: unavailable` with a reason, without zero-valued process identities. Windows generations use process creation FILETIME; Linux generations combine boot ID and process start ticks. Compare the complete daemon and worker identities at every experiment stage; equal capture/context/replay IDs cannot establish continuity across process replacement. This is process provenance, not proof of native arithmetic, restoration or device presentation. It adds no lifecycle or shell authority and exposes no daemon token.

## Android connection ownership

Android connect reuses an existing helper without APK installation, configuration changes or activity launch. If none is running, connect starts its own helper. The owned-helper path resolves RenderDoc's config location from the device SDK level (`Android/data` below 30, `Android/media` from 30 onward), preserves an existing `renderdoc.conf`, creates an empty default only when the file is absent, and rejects an unknown SDK or file state instead of overwriting it. A helper PID is not evidence of service occupancy: success requires the actual RenderDoc connection and Ping. A single timeout budget covers bootstrap and connection; socket readiness waits no more than 15 seconds. Borrowed services use connection-only shutdown; only verified owned PIDs and ADB forwards may be removed. No additional user mode or versioned interface is introduced.

A stopped helper process does not make an existing package or configuration owned by this connection. Before installing, a successful package-manager query must confirm that the exact helper package is absent; unknown, failed or malformed query results fail closed. An installed package is reused without a local APK dependency, replacement install, uninstall or configuration creation. Only a newly installed helper may receive a missing default configuration. A fresh installation is attempted once without replacement flags; conflicts, signature/version errors and package-install races are reported without uninstalling or retrying. Process and forward ownership remain separate from installation ownership. Historical bootstrap metadata remains readable; it never authorizes a new mutation.

Native device presentation is part of `rd.session.observe`, using the owning remote replay connection. Its `remote_display` identifies the applied event, selected texture and fresh completion sequence, with `presented`, `unavailable`, `unsupported`, or `not_applicable` status. No-color observations clear the device surface. PNG output does not establish presentation. Native client/helper protocol and runtime manifests are paired; an incompatible helper is rejected without compatibility forwarding. The reusable Android development signing keystore is retained outside disposable build directories, so future same-install helper upgrades preserve app data.

## Restored data capabilities

Capture thumbnails read embedded capture data without replay. Structured API queries expose captured chunks, typed fields and bounded continuation, not a complete process API trace. Resource details expose recorded initialization chunks and relationships; descriptor stores expose bounded ranges including empty slots and unaccessed descriptors.

Resource identities use the same exact matching for native IDs, decimal strings and `ResourceId::<decimal>` strings, without floating-point conversion or substring matching. Resource details reuse the completed texture/buffer/descriptor-store/description inventory. A genuine inventory miss returns `validation/resource_not_found` with `effects_attempted=false`, `context_preserved=true` and `failure_stage=resolve_resource` before binding enrichment; a failed inventory read never receives that proof. This error remains a rejection, not an empty successful resource or a claim that a resource contributes zero.

Numeric texture readback decodes packed R10G10B10A2_UNORM and B10G10R10A2_UNORM using the declared native channel order, ten-bit color and two-bit alpha normalization. Mip/slice/sample and region selection retain their existing semantics. A packed name does not authorize guessing other component types; short readbacks and unsupported formats remain errors.

Requested pipeline sections preserve viewport/scissor and output-slot indices and native facts. Qualification applies only to requested sections: uncollected model defaults cannot degrade returned bindings or imply that the omitted shader/output state was inspected. Requested facts that are genuinely missing retain their degraded qualification. API applicability, missing data and failure remain distinct. Dynamic declarations absent from capture data remain unknown.
For operations that access a replay controller, the native `GetFatalErrorStatus` is checked before first access and again before results are published. Semantic argument validation still runs before controller access. `replay_fatal_error` requires controlled recovery; a missing or invalid health probe is `replay_health_unavailable`, never presumed healthy. RenderDoc can return default zeros, empty objects or API properties after a fatal error, so these are not successful measurements. Healthy zero/empty results remain valid. Lifecycle cleanup remains available. This check detects an unusable replay; it does not establish why a remote connection failed or prove experiment restoration.

Texture and buffer reads distinguish `current` and `capture_initial`. Initial reads require recorded initial-data provenance and restore the original event; unavailable provenance is an error, never a current-data fallback. Restoration failure quarantines the session. Inline bytes are bounded; explicit output requests control persistence.

Whole-frame timing uses GPU timestamps for complete replay on a verified single queue. It excludes initial-state reconstruction and includes replay scheduling gaps. It is not original application frame time, CPU elapsed time or an event-duration sum. Method, range, unit, sampling conditions and individual samples accompany the result. Unsupported backends or incomplete queue coverage cannot produce a valid measurement.

## Mesh and shader provenance

Successful `rd.shader.edit_and_replace` results retain `replacement.compile.build_input`: the exact bytes passed to that invocation of `BuildTargetShader`, their SHA-256 and size, the encoding, the original shader ID, and the target shader ID returned and passed to `ReplaceResource`. This is build-input provenance, not a shader readback or device ISA proof (`device_binary_observed: false`). For binary SPIR-V input, `spirv_header` exposes the actual header words including `id_bound` only when a complete aligned recognized header is present; it does not validate instruction semantics. Text inputs, malformed headers and no-op builds do not synthesize a binary bound. Failed builds do not report an applied-target proof. Before/after source hashes remain distinct from the build-input byte hash. When patch artifacts are requested, the same byte sequence is saved as `artifacts.build_input` (.spv for SPIR-V module input, .txt for source input); otherwise no extra byte artifact is written. The raw bytes stay out of ordinary model JSON serialization. Historical results without this provenance are not retroactively certified. Event-bound `extract_binary` continues to inspect the bound reflection and does not silently select a replacement target.


A rejected `rd.shader.edit_and_replace` diff remains a `shader_patch_diff_failed` validation failure. If textual diff application failed before compilation or replacement, the Tool explicitly reports `failure_stage: apply_patch`, `replacement_attempted: false` and `context_preserved: true`. The replay may already have navigated to the requested event, so this is not a no-effects claim, restoration proof, intervention or rollback. Unknown/native/replacement failures do not inherit this proof; consumers still verify the frozen owning lease before permitting another request.

Vertex input queries decode declared formats, offsets, bindings, indices and instance rates in original shader-input coordinates. Values retain their semantic names; unknown or ambiguous semantic mappings remain unsupported. Normalized integer NORMAL data is not automatically a geometric normal. Post-transform signature outputs use independently verified native packing and never substitute input attributes. D3D11/12 stream-zero float output packing and Vulkan VS per-vertex stream-zero float32 std430 packing are separate API layouts. Vulkan requires a unique leading float4 Position, unique explicit varying locations and exact native-stride agreement; its API/stage-tagged layout exposes native location/builtin, variable name, component mask (null if unavailable), scalar type, byte offset and component count, with per-row `location:N` / `builtin:Name` keys. Other Vulkan stages, types, rates, ambiguous locations or mismatched layouts stay explicitly unsupported; incomplete raw bytes fail and nonfinite decoded values remain null. A native component mask alone does not prove component/interpolation mapping at the raster interface. Vertex output availability does not establish raster interpolation, sample/primitive coverage or pixel-shader operands. OBJ normal/UV export requires explicit VS input space and matching float attributes; post-VS OBJ remains positions only.

Shader `resource_name` is the native display name (including autogenerated labels); `debug_name` is a custom shader resource name or null. `debug_source_files` contains source filenames and does not imply a shader debug name. Marker paths preserve parent ordering and duplicate labels.

`rd.shader.get_source` reads captured `ShaderDebugInfo.files` only. It preserves native file order, filenames and contents; the first file is the entry source. A filename never authorizes reading that path on the host. `source_debug_information=false` only denies source-level debugging and does not mean embedded source text is absent. Source encoding, source entry name and compile flags come from native debug metadata and remain null when unavailable. Empty file lists or missing entry contents return explicit source-unavailable results (retaining any include text); absent native metadata and native read failures return distinct errors. An unavailable source never yields an editable/buildable/replaceable edit plan. Read failures verify prior-event restoration, and failed restoration remains an explicit recovery failure.


`rd.shader.get_reflection` exposes RenderDoc's event-bound `debugInfo.debuggable`, `sourceDebugInformation`, and `debugStatus` under `reflection.debug_info`. A missing native field is `null`; an empty status is only an absent explanation. Source debug information and shader debuggability are separate facts, and `debuggable: true` does not guarantee that `DebugPixel` will return a usable debugger handle for a particular pixel. `rd.shader.debug_start` validates the target against Pixel History for the requested Event before accepting a native trace. An explicit target is authoritative; otherwise it selects from that Event's output targets and uses the default output only when none are available. Zero current-Event hits cannot establish a target-bound trace, even if native `debugger` is non-null. `ShaderDebugTrace` has no `valid` field.

Pixel History preserves native reported values; it does not promise an executable per-fragment blend ledger. Interpret shader-out channels with the output format and backend/build semantics. Native Vulkan implementations can zero channels beyond the target component count, leave an event-final post-modification value on the last fragment, and reconstruct per-fragment depth-test flags from quantized depth comparisons. A reported zero in an absent target channel does not independently establish the original shader output, and a changed post-modification value alongside a failed fragment does not independently attribute that write to the fragment. These implementation-dependent qualifications do not certify the source revision of an installed local or remote binary. Preserve raw values and unknown validity; corroborate with event-bound texture reads, pipeline state and valid shader-debug output before inferring blend or depth faults.

`rd.shader.get_disassembly` accepts `auto`, an exact current disassembly target, or the explicit `SPIR-V ASM` raw request. An unavailable target is rejected before applying an event. Its canonical validation error includes the available targets and `effects_attempted: false` with `context_preserved: true`. Those fields certify only that this request did not attempt a replay effect; other disassembly failures still follow the ordinary uncertain-outcome recovery contract.

`rd.export.shader_bundle.disassembly_target` selects the same exact view as `rd.shader.get_disassembly` (`auto` by default). Request `SPIR-V ASM` explicitly to save editable assembly as a workspace file for independent compilation; the default presentation view is not assembler input. The bundle records the returned target, encoding, raw-ASM qualification, source hash and edit plan alongside the exact UTF-8 file hash and size. Failed or mismatched explicit targets remain unavailable with `complete=false`; the exporter never substitutes another view. Compilation and replacement remain separate capabilities and are not implied by an export.



`rd.shader.get_constant_buffer_contents.slot` is the zero-based index in the stage's reflected `constantBlocks`, as consumed by RenderDoc `GetConstantBlock` and `GetCBufferVariableContents`. It is not an API-specific fixed binding number; `set_or_space` retains the reflected native set/space. Current `UsedDescriptor.descriptor` supplies buffer identity, byte offset and size. Native constant-buffer decoding passes the stage-bound `ResourceId` object, never its serialized ID string; an available raw-byte fallback remains explicitly degraded and is not proof that structured decoding succeeded. Missing data remains an error. A known `constant_buffer_data_unavailable` failure restores and verifies the original active event before attaching context/session/event recovery proof; an unknown original event or failed restoration cannot claim preservation. This proof is not an experiment rollback or a successful constant-buffer read.

Constant-buffer `max_bytes` is a per-block input byte budget (default 1048576); zero retains the uncapped-block behavior and negative values are invalid. The native complete-layout decoder is not called when the permitted input does not cover the reflected block, its binding is too short, its extent is unknown, or a buffer-backed block is unbound. Such input cannot produce padding-derived typed zero values. `input_coverage` reports the required extent, binding size, budget and permitted range; `decode_input_bytes` records the decoder length argument, not an independently observed byte-read receipt. `decode_status` distinguishes decoded values, unavailable decoding and explicit raw fallback. Full-input decoded zero remains a legitimate value. Metadata-only queries do not claim to decode values.

A raw fallback reads only the permitted constant-block range and verifies the actual byte count; short, empty or overlong native readbacks fail rather than becoming a successful empty block. `raw_fallback.byte_size` is the observed count, `requested_bytes` is the actual bounded request and `block_bytes` is the required extent. `truncated` concerns block coverage; `preview_bytes` and `preview_truncated` separately describe the at-most-256-byte hex preview. A full block read does not mean that all its bytes were delivered in that preview. Constant-buffer dumps propagate unavailable requested decoding and bounded raw prefixes as `partial`, retaining per-block errors and coverage in the saved JSON. These fields establish input qualification, not shader execution or native GPU arithmetic. Old outputs without coverage are not retroactively certified by this contract.



`rd.event.search_actions` accepts native RenderDoc ActionFlags member names in `flags_include` / `flags_exclude` (for example `Drawcall`, `Dispatch`, `Present`), not projected result fields such as `is_draw`. Invalid flag names or flag-array shapes are rejected before controller acquisition or action-index loading, with canonical `validation_error` and `effects_attempted: false`, `context_preserved: true`. Other failures do not inherit that proof.

Shader-debug handles are scoped to the owning replay session. `rd.shader.get_debug_state` and `rd.debug.*` reject missing/foreign handles as canonical `shader_debug_handle_invalid` validation failures before acquiring a controller or applying an event, with `effects_attempted: false` and `context_preserved: true`. A valid debug-state request retains its event application behavior. Native failures after validation do not inherit this proof. Reopening the same capture does not make a historical debug handle valid.

Native shader debugging consumes every state returned by RenderDoc `ContinueDebug`, in order. PC means the monotonic trace `stepIndex`, not a SPIR-V result ID or source line. Variable snapshots accumulate typed `ShaderVariableChange.before/after` updates and remove variables that leave scope; an initial empty snapshot is valid. `get_variables` uses a literal name filter, bounded member depth and explicit truncation. Only instruction stepping and non-negative PC targets/breakpoints are implemented; unsupported source positions and step modes fail before native access. Call stacks preserve native function names, with unknown source file/line reported as null. Expression evaluation supports exact current variable names or JSON literals only. A failed native trace release retains the handle and propagates the error.

Image file differences compare decoded normalized RGBA values and honor the selected `mse`, `max_abs`, `psnr`, `ssim` metrics (default: the first three). Unknown or empty metric selections fail explicitly; no requested metric is silently omitted. Identical PSNR is JSON null with `psnr_status=infinite`. SSIM uses valid 11x11 Gaussian windows, sigma 1.5, population covariance, data range 1 and the mean of RGBA channel scores; images smaller than 11 pixels in either dimension fail when SSIM is requested. It does not resize or align images. Diff PNGs are opaque RGB, with alpha differences visualized as gray rather than output transparency. A difference score describes a change, not whether it repairs rendering. Reference: Wang et al., https://www.cns.nyu.edu/pub/eero/wang03-reprint.pdf.

`rd.util.diff_images` optionally compares an explicit pixel `region` (`x`, `y`, `width`, `height`) in both equally sized source images. It rejects empty, malformed and out-of-bounds rectangles instead of clamping. Metrics report the original `source_size` and effective `region`; an exported diff has region dimensions. SSIM's 11-pixel minimum applies to the selected region. Omitting region preserves whole-image measurement. This supports separate target and control measurements without changing input images or replay identity.

`rd.shader.get_debug_state.summary` reports the dynamic trace PC separately from native `next_instruction`. Native `instInfo` is a sparse sorted interval map: the preceding entry applies until the next entry, including across loops and branches. `source_location` is null when unavailable; unknown source indices/lines/columns remain null. Its 1-based `disassembly_line` refers only to RenderDoc native debug disassembly, never automatically to raw SPIR-V ASM, SSA IDs or device ISA. `full` adds up to 64 current mutable variables at member depth 2 and 64 native call-stack names, with counts and truncation flags; the ordinary variable query retrieves a more focused view. Neither view promises arbitrary SSA/register visibility or constant/immutable values. Step/run-to/breakpoint state responses reuse the same summary projection. `has_native_state: false` distinguishes an initial PC 0 placeholder from an observed native state. Invalid detail levels are rejected before native access with no-effects proof. Terminal continue/step results retain their explicit finished reason; a separately queried state remains the last observed native state.


## Live capability and disassembly discovery

`rd.core.get_capabilities(detail_level=summary)` and ordinary context reads do not resume replay controllers. `full` uses the normal session-recovery path for the selected session only and probes native capabilities on the replay thread. `current_session_probe` distinguishes verified, unavailable (with reason/code), and not_currently_probed. Deferred recovery and probe failures do not establish unsupported shader functionality. Persisted endpoint metadata is not a live-connection receipt; current-process loaded counts are not counts of persisted sessions. A targetless Present event does not disprove shader inspection at an actual draw.

Successful `rd.shader.get_disassembly` results include native `available_targets`, `available_targets_status`, and `available_targets_error`. Complete empty lists, failed queries, and absent native interfaces remain distinct. These enumerate native disassembly views, not an assurance of GPU ISA availability or the Tool's independent raw-SPIR-V assembly fallback. Interpret the selected `target`, `is_raw_spirv_asm`, and `edit_plan` separately. Invalid-target discovery failures still precede replay-event changes and carry explicit no-effects proof.

Raw SPIR-V classification requires actual opcode lines. Headers, comments, diagnostic messages, and a backend's accepted source-encoding hint alone do not establish editable assembly. Explicit raw targets and external raw-disassembly fallback must also return instructions. Other native views retain their original text for inspection; an informational or failed native-view response cannot authorize compilation or replacement through an inferred raw-ASM edit plan. Opcode recognition is a format check, not complete validation or evidence of GPU execution; normal compilation and replacement validation remain required.


`rd.texture.get_region_values` provides a complete inline `values` array when its sampled, converted readback contains at most 256 scalar values. Larger arrays return `values: null` with `values_status: omitted_limit`; they are not silently truncated. `inline_value_limit` declares the bound. The existing full NPZ at `values_path` represents that same array and remains available for exact bulk readback. Region and whole-texture statistics share one calculation over the actual stride samples; aggregate and per-channel finite min/max/mean and NaN/Inf counts are distinct. Decoded component labels do not prove physical alpha or blending semantics. Non-finite inline samples retain canonical string markers. These outputs enable numerical inspection, not automatic quality acceptance.


Shader rollback preserves the original replay controller and connection; it never silently reopens them. Worker transport loss or an unexpected worker error fails with an unknown outcome and no automatic resubmission. Existing session/capture/replacement metadata remains available under `requires_restart` until explicit lifecycle cleanup; recovery scans cannot turn that state into ready or deferred. Consumers must not mint rollback/restored evidence from worker restart or capture reopening.

Client cleanup and the daemon lifecycle share the same unreleased-resource check. Idle time alone cannot stop a live daemon holding a capture, replay, remote ownership, or an active request; an expired lost-owner lease still permits cleanup. Unreadable ownership state is retained for controlled recovery. A newly started or replaced worker marks persisted replay sessions `requires_restart` before dispatch, retaining their metadata; requests never spawn a replacement worker implicitly. Explicit context cleanup remains available. Persistent session IDs and equal image hashes do not establish continuity across worker replacement.


`rd.mesh.get_post_transform_data` optionally accepts a VS `first_index`/`index_count` window. Ordinals are index elements; `decode_index_data.index_offset` remains bytes. Window mode requires explicit `max_vertices` 1..256 and 1..4096 indices, and reads at most 1 MiB of actual index plus referenced output rows using only the native MeshFormat resource objects. Sparse rows retain original vertex identity, source byte offsets, raw index bytes and index-to-row mapping; it does not enumerate arbitrary internal IDs or replace output data with input data. Native base vertex and finite view bounds are checked; unbounded native views remain null in window-bound fields. Short reads and budget failures are errors, never zero-filled success. Restart matches are candidates, not proved raster primitives, and make vertex mapping incomplete. Window completeness is distinct from whole-draw completeness. Invalid arguments and specific buffer resolution/range/budget rejections that precede event changes or data reads carry explicit no-effects/context-preserved proof. Inventory/native-health or post-effect failures retain uncertain outcomes; consumers must not infer preservation from an error name.

`rd.resource.list_all` with `kind=all` adds `identity_inventory`: a complete, exact, deduplicated identity census from GetTextures, GetBuffers, GetDescriptorStores and GetResources, the same four native inventories used by resource-details resolution. It reports scope `all_native_resource_identities`, `complete=true`, `resource_ids`, `count` and individual `source_counts` only after all reads succeed. IDs remain strings, including values above 2^53. The existing `resources` rows and their tabular projection describe textures, buffers and descriptor stores; absence from those rows alone is not absence from the full native census. A filtered `kind` has no global identity-completeness claim. A failed native inventory is an error, never an empty complete census or proof of preservation. This census establishes identity membership, not pixel usage, causality, or a rendering contribution.


### Independent shader compilation

`rd.shader.compile` accepts raw SPIR-V ASM through `source_text` or `source_path`. It selects the native advertised ASM encoding when available; on a binary-SPIR-V backend it uses the same local `spirv-as` assembly path as PatchEngine and submits the resulting module to `BuildTargetShader`. It never replaces a resource. The result distinguishes requested `source_encoding` from actual `build_encoding`; `build_input` identifies the exact bytes accepted by native construction, with `device_binary_observed: false`. For assembled SPIR-V, the exported `artifact_kind: assembled-spirv-build-input` is that module, not device code or a native readback. Other native readback exports are qualified as `native-shader-readback`.

Input/encoding rejection and local assembly failure occur before native construction and explicitly return `effects_attempted: false` and `context_preserved: true`. Exceptions or failures after `BuildTargetShader` begins do not acquire those guarantees. The application continues to quarantine uncertain native outcomes. Assembly/disassembly temporary files use the configured intermediate runtime root and are released on success, rejection and timeout.
